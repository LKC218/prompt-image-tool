## 1. 问题与目标

### 1.1 当前问题

| # | 现象 | 根因判断 |
|---|------|----------|
| P1 | 顶部约 6–12px 黑边去不掉 | Win11 WebView2 + pywebview 无边框残余非客户区；`DwmExtendFrameIntoClientArea(-1)` + 拆 `WS_CAPTION` 不足以消除 |
| P2 | 每次最小化再还原，窗口比 1600×900 更小 | 无边框样式被改后，`WM_GETMINMAXINFO` / 还原量测用错非客户区尺寸，尺寸逐次漂移 |
| P3 | 默认窗口不是稳定 16:9 的 1600×900 | 尺寸只写在 `create_window` 初值，无「还原后纠偏」；DPI / 工作区夹取后无等比策略 |
| P4 | 双壳分叉成本高 | 正式包是 PyInstaller+pywebview；Tauri 半成品且依赖本机 Python；窗口问题只能在脆弱链路上修 |

### 1.2 目标

1. **Windows 正式桌面壳唯一收敛为 Tauri 2**（主流：Electron/Tauri 式无边框 + 自绘顶栏 + 壳层处理命中测试）。
2. 黑边、最小化缩尺寸、默认 1600×900 三项由 **Tauri/WRY 原生窗口栈** 解决，不再在 WebView 里用 Win32 硬补。
3. Python 仅保留 **HTTP 数据后端**（现有 `/api/*` 不变），以 sidecar 方式随包分发，不要求用户自装 Python。
4. 现有前端自绘顶栏（`.pc-window-chrome`）保留视觉，窗口控制统一走 Tauri Window API。

### 1.3 非目标

- 不重写前端业务、不改数据模型、不迁移 Android。
- 不把 Python 后端改写成 Rust（工作量与收益不成正比）。
- 不做 macOS / Linux 壳。
- 本阶段不实现 Win11 Snap Layouts 悬停面板（可作后续增强）。

## 2. 方案选型（已拍板）

| 方案 | 说明 | 结论 |
|------|------|------|
| A. Tauri 收敛 | 无边框交给 Tauri，`decorations:false` + 自绘顶栏 + Window API | **采用** |
| B. 继续 pywebview + `WM_NCCALCSIZE` 子类化 | 在 WebView2 残余 NC 上硬扛 | 否：长期脆、Win11 更新易回退 |
| C. 换 Electron | 自定义 chrome 最成熟 | 否：体积与内嵌成本高于 Tauri |

**风格锚点**：VS Code / Discord / Notion 桌面端 —— 全客户区 + 自绘顶栏 + 壳层负责拖动/最小化/最大化/关闭与圆角阴影。

## 3. 目标架构

```text
┌──────────────────────────────────────────────────────────┐
│  Tauri 2 NSIS 安装包（唯一正式 Windows 壳）                  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ WebView2（前端 dist/）                                │  │
│  │  · 自绘顶栏 pc-window-chrome（拖动区 + 窗口按钮）     │  │
│  │  · 业务页面（目标计划 / 提示词库 / …）                 │  │
│  └───────────────────────┬────────────────────────────┘  │
│                          │ fetch http://127.0.0.1:8888    │
│  ┌───────────────────────▼────────────────────────────┐  │
│  │ Sidecar：PromptImageManager-Server.exe              │  │
│  │  （PyInstaller 无头打包 python/main.py 逻辑）         │  │
│  │  · /api/*  · 数据目录  · 更新  · LAN 同步             │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  Tauri 窗口层（WRY）：                                     │
│   decorations:false · shadow:true · 1600×900 · 还原纠偏   │
└──────────────────────────────────────────────────────────┘

冻结不进主链（仅应急）：
  build/app_main.py + pywebview + PyInstaller 全量包
```

### 3.1 窗口契约（P1–P3 落点）

| 项 | 做法 |
|----|------|
| 黑边 | 不再手写 `strip_native_caption` / DWM margins；Tauri `decorations:false` + 默认 Win11 圆角阴影。若特定机仍见残边，仅允许在 Tauri 窗口配置层处理（如 `transparent` 实验），禁止回退 WebView 内 Win32 |
| 尺寸 | `tauri.conf.json`：`width:1600, height:900, minWidth:1024, minHeight:576, center:true`。启动后一次 `outer_size` 校验；小于工作区时按 **16:9 等比** 缩到工作区内并居中 |
| 最小化 | 最小化前由前端/Tauri 记录逻辑尺寸；`unminimize/restored` 后若 `outer_size` 高度或宽度小于记录值且未最大化，`setSize` 拉回记录值。禁止每次还原硬写 1600×900（用户手动调过的尺寸要保留） |
| 顶栏 | 沿用 `renderWindowChrome()`；`data-tauri-drag-region` 已存在；窗口按钮只调 `@tauri-apps/api/window`（`minimize/maximize/unmaximize/close/toggleMaximize/startDragging`） |
| pywebview 桥 | `pc-window-chrome.js` 保留 `getPywebviewAdapter` 作应急兼容，主路径断言 Tauri；新逻辑只加 Tauri 分支 |

### 3.2 Sidecar 契约

1. 以 **无头** 入口打包 Python HTTP 服务（复用 `python/main.py` 与 `build/app_main.py` 中服务逻辑的并集，见任务 T3）。
2. 监听 `127.0.0.1:8888`（占用则递增，把实际端口写到约定文件或 stdout JSON，前端 `storage.js` 启动时读取；`API_BASE` 现写死 `http://localhost:8888`，需改为可发现）。
3. Tauri `setup` 里用 `tauri-plugin-shell` spawn sidecar；退出时 kill；端口未就绪时轮询 `/api/health`。
4. 数据目录约定与现实现一致（用户数据不迁移路径，升级零拷贝）。

## 7. 风险与回退

| 风险 | 缓解 | 回退 |
|------|------|------|
| Tauri `decorations:false` 在个别 Win11 版本仍见残边 | Phase 1.4 实机双版本抽测；保留配置层实验项 | 单点热修 Tauri 窗口配置，不回 pywebview |
| Sidecar 端口/杀进程异常导致数据不可用 | health 门闩 + 启动失败明确报错 | 应急旧壳 PyInstaller 包仍可发一版 |
| NSIS/自动更新布局变化使更新失败 | Phase 3.4 先在虚拟机跑一轮 | 手动全量安装包旁路 |
| 用户仍停留在旧 pywebview 包 | 更新说明与安装向导提示 | 不强制卸载；数据兼容 |

## 9. 已确认决策

- 正式 Windows 壳：**Tauri 2**（方案 A）。
- 默认窗口：**1600×900**，不足按 16:9 等比缩。
- 顶栏形态：**自绘顶栏**（现 `.pc-window-chrome`），不保留系统标题栏。
- Python 后端：**保留 HTTP API**，sidecar 分发；不重写 Rust。
- pywebview 全量包：**冻结为应急**，不再修窗口问题。
