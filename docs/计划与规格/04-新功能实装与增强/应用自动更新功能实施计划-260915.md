# 应用自动更新功能实施计划

> 创建日期：2026-09-15
> 状态：已实施（代码已接入，待发版验证端到端）
> 分类：04-新功能实装与增强
> 目标端：PC（生产包为 PyInstaller + NSIS；Tauri 仅开发壳）

> **架构校正**：用户安装的是 `PromptImageManager-Setup-*.exe`（PyInstaller + pywebview + Python HTTP API），不是 Tauri 运行时。更新能力实现在 Python 后端与前端 HTTP 调用，而非 Tauri command。

---

## 一、已确认决策

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 更新实现方式 | **自建下载 + 静默安装**（不使用 `tauri-plugin-updater`） |
| 2 | 托管方式 | **GitHub Public Releases** 固定托管 |
| 3 | 检查时机 | **启动自动检查**（静默，不打断） |

讨论共识：

| 结论 | 说明 |
| --- | --- |
| 可以做自动更新 | 应用内检查 + 下载 + 覆盖安装 |
| 不能 git pull 源码 | 用户装的是 NSIS 二进制，不是源码仓库 |
| 分发源 = Releases 资产 | 安装包 + `latest.json`，不扫仓库文件 |
| 主流闭环 | 查版本 → 下产物 → 校验哈希 → 静默安装 → 重启 |

## 二、目标与范围

### 2.1 目标

PC 端具备自建应用内更新：启动静默检查 GitHub Public Releases 的 `latest.json`，发现新版本后提示用户，确认后下载安装包、校验 SHA256、静默覆盖安装并重启。

### 2.2 范围内

- 自建检查 / 下载 / 校验 / 静默安装链路
- 发布侧生成并上传 `latest.json` + 安装包
- 启动自动检查 + 设置页手动检查
- 下载进度、失败重试 UI
- 版本号与现有 `getVersion()` 对齐

### 2.3 范围外（本期不做）

- 官方 `tauri-plugin-updater` / minisign
- 移动端更新
- 增量/差分更新
- 私有仓库鉴权
- 自动回滚

## 三、技术方案（自建）

### 3.1 整体流程

```
[应用启动]                    [设置页手动检查]
      │                              │
      └──────────┬───────────────────┘
                 ▼
        请求 latest.json（匿名 HTTPS）
                 │
                 ▼
     比较远程 version 与 getVersion()
                 │
          ┌──────┴──────┐
          │ 无更新       │ 有更新
          ▼             ▼
     静默返回/提示最新  角标或弹窗「发现新版本」
                         │
                         ▼
                    用户确认更新
                         │
                         ▼
              下载 NSIS 安装包到临时目录
                         │
                         ▼
                 校验 SHA256 哈希
                         │
              ┌──────────┴──────────┐
              │ 失败                 │ 通过
              ▼                     ▼
         报错可重试          以 /S 静默启动安装器
                                   │
                                   ▼
                            退出当前应用进程
                                   │
                                   ▼
                             安装完成后用户重启
                             （或安装器拉起新版本）
```

### 3.2 关键选型

| 项 | 选型 | 理由 |
| --- | --- | --- |
| 更新方式 | 自建 | 已确认；控制力强，依赖少 |
| 运行载体 | Python HTTP API + 前端 | 生产包为 PyInstaller，无 Tauri 运行时 |
| 配置文件 | `latest.json` | 扁平 JSON，字段自控 |
| 分发托管 | GitHub Public Releases | 匿名 HTTPS，无需 token |
| 完整性校验 | SHA256 | 发布时计算并写入 `latest.json` |
| 静默安装 | NSIS `/S` | 现有 bundle target 已是 nsis |
| 安装模式 | `currentUser` | 与现有配置一致，降低 UAC 风险 |
| 版本来源 | `getVersion()` | `src/index.html` meta version 单一入口 |
| 下载落点 | 系统临时目录 | 安装后可清理，不污染用户数据目录 |
| 调用通道 | Tauri command（Rust） | 下载/哈希/拉起安装器放 Rust，前端只做 UI |

### 3.3 `latest.json` 约定（自建扁平结构）

```json
{
  "version": "2.5.3",
  "pub_date": "2026-09-15",
  "notes": "见更新说明",
  "platform": "windows-x86_64",
  "url": "https://github.com/<owner>/<repo>/releases/download/v2.5.3/生图提示词管理器_2.5.3_x64-setup.exe",
  "sha256": "<64位十六进制>"
}
```

托管地址固定为：

```
https://github.com/<owner>/<repo>/releases/latest/download/latest.json
```

安装包使用 Release 内固定命名，URL 写入 `latest.json`，应用不解析 Releases HTML。

### 3.4 不推荐 / 禁止

1. **git pull / clone 覆盖安装目录**
2. **解析 GitHub Releases 页面 HTML**
3. **只比版本号、不校验 SHA256**
4. **启动时无提示直接强制安装**（启动只检查与提示，安装须用户确认）

## 四、发布侧产物约定

每次发版在 GitHub Release 至少包含：

| 资产 | 说明 |
| --- | --- |
| `生图提示词管理器_x.x.x_x64-setup.exe` | NSIS 安装包（现有命名） |
| `latest.json` | 自建更新元数据（含 version / url / sha256） |

发布脚本职责：

1. 读取单一版本源（与 `package.json` / meta version 一致）
2. 计算安装包 SHA256
3. 生成 `latest.json`
4. 随安装包一并上传 Release，并保证 `releases/latest/download/latest.json` 可访问

## 五、实施阶段划分

### 阶段 A：发布链路改造（优先）

| 任务 | 产出 | 涉及 |
| --- | --- | --- |
| A1 发布脚本计算 SHA256 并生成 `latest.json` | 脚本步骤 | `scripts/build_release_packages.py`、发布脚本/skill |
| A2 Release 上传 `latest.json` + 安装包 | 固定命名 | `.mimocode/skills/release-publish/` |
| A3 验证 `releases/latest/download/latest.json` 匿名可访问 | 手测清单 | 仓库 Release |
| A4 发版必做清单补「更新元数据」 | 文档检查项 | `docs/工程指南/版本发布与更新记录维护指南.md` |

### 阶段 B：应用侧自建更新

| 任务 | 产出 | 涉及 |
| --- | --- | --- |
| B1 Rust command：获取 `latest.json` | `check_update` | `src-tauri/` |
| B2 Rust command：下载安装包到临时目录并校验 SHA256 | `download_update` | `src-tauri/` |
| B3 Rust command：`/S` 静默拉起安装器并退出应用 | `install_and_restart` | `src-tauri/` |
| B4 前端状态与 API 封装 | 可复用模块 | 建议 `src/js/release/auto-updater.js` |
| B5 设置页「检查更新」 | 手动入口 | `pc-settings.js` |
| B6 启动静默检查 + 角标/轻提示 | 不打断启动 | `pc-app.js` |
| B7 下载进度、失败重试、确认安装弹窗 | UI | 复用 `pc-utils.js` |
| B8 权限与 Tauri 允许清单 | capabilities | `src-tauri/capabilities/default.json` |

**建议 command 语义：**

| Command | 输入 | 输出 |
| --- | --- | --- |
| `check_update` | 本地 version | `{ hasUpdate, latest }` 或网络错误 |
| `download_update` | url, sha256 | 本地临时路径 / 进度回调 |
| `install_and_restart` | 本地安装包路径 | 拉起后退出进程 |

### 阶段 C：验证与收口

| 任务 | 验收标准 |
| --- | --- |
| C1 旧版 → 新版覆盖安装 | 用户数据与配置保留 |
| C2 SHA256 不匹配 | 拒绝安装并报错 |
| C3 断网 / 超时 / 下载中断 | 启动不阻塞，可重试 |
| C4 已是最新 | 手动检查提示「已是最新」；启动静默 |
| C5 启动检查失败 | 静默失败，不弹错误打扰 |
| C6 与更新记录弹窗共存 | 互不抢焦点 |
| C7 测试 | vitest（前端状态）+ 人工安装回归清单 |

## 七、风险与对策（决策已定）

| 风险 | 对策 |
| --- | --- |
| GitHub 限流 / 不稳定 | 仅启动检查一次；失败静默；支持手动重试 |
| 私钥/鉴权 | Public 仓库无需 token，无 Secrets 成本 |
| UAC / 安装权限 | 保持 `currentUser`；真机验证 `/S` 无提升 |
| 安装器壳与 `/S` | 阶段 A/B 后做一次真实静默安装验证 |
| 下载中途篡改 | 必须校验 SHA256，失败不执行 |
| 强制更新体验差 | 启动只提示，安装必须用户确认 |
| 版本号多源 | `latest.json` 由发版脚本从单一版本源生成 |

---

## 八、落地顺序（最短路径）

1. **阶段 A**：发版能稳定产出匿名可访问的 `latest.json` + 安装包 + SHA256
2. **B1**：跑通「启动/手动检查到新版本」
3. **B2–B3**：跑通「下载 + 校验 + `/S` 安装」
4. **B4–B8 + C**：补 UI、启动静默检查与验收
