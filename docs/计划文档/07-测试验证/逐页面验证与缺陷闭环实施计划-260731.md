## 一、目标与边界

建立可重复执行的逐页面验证标准：以页面、控件和业务结果为最小验收单位，覆盖双端核心页面、容器能力与发布链路；所有确认缺陷均形成“复现、定位、最小修复、定向复测、影响回归、自动化补测”的闭环。

本计划是后续测试批次的执行手册，不记录每次执行的实时结果。执行结果、环境阻塞和缺陷状态应记录到独立测试记录或缺陷清单，避免污染固定验收标准。

### 完成标准

- PC Web 与移动端 Web 的首页、提示词库、提示词详情、编辑器、分类与标签、设置页面均完成检查矩阵。
- PC 详情弹窗、安装器壳 7 步流程、Tauri 与 Android 的原生能力均按适用条件完成验证或明确记录环境阻塞。
- 每个可操作控件至少覆盖成功、取消或失败、重复操作和状态刷新；破坏性操作必须覆盖确认与取消。
- 自动化基线、生产构建与构建产物资源检查均保留可追溯证据。
- 所有 P0/P1 缺陷关闭；P2/P3 缺陷已分级、评估发布风险并建立后续处理项。

### 非范围

- 不以视觉像素级差异作为本计划的通过条件；视觉问题仅在造成可读性、可点击性、遮挡或跨端功能不一致时登记。
- 不在共享默认数据目录执行保存、删除、导入、导出、同步或清理操作。
- 不将浏览器自动化会话异常、缺少工具链或设备不可用直接判定为产品缺陷，除非已取得应用日志、网络证据或稳定复现步骤。

## 三、统一页面检查规则

### 3.1 每页固定检查维度

| 维度 | 检查内容 | 通过标准 |
|---|---|---|
| 进入与路由 | 入口、刷新、前进、后退、未知路由 | 正确渲染目标页，历史状态和当前导航态一致 |
| 数据状态 | 加载、空数据、正常数据、错误与重试 | 状态可理解、可恢复，数据不被错误覆盖 |
| 控件交互 | 所有按钮、菜单、链接、输入、快捷键 | 可见、可达、语义清晰，触发正确业务结果 |
| 取消与失败 | 取消弹层、文件选择取消、校验、权限、网络、存储失败 | 提示可行动，数据保持安全，焦点和页面状态恢复 |
| 重复操作 | 连点、重复提交、重复打开、重复导入 | 不产生重复数据、异常弹层、死锁或崩溃 |
| 持久化与联动 | 刷新、跨页返回、列表和详情同步 | 已确认操作的结果一致且可恢复 |
| 可用性 | 键盘焦点、Escape、弹层焦点归还、窄视口、文本溢出 | 无控件遮挡、不可达或焦点丢失 |
| 运行证据 | 控制台、网络、资源加载、接口状态 | 无未处理错误、关键请求失败或静态资源 404 |

### 3.2 执行顺序

1. 只读冒烟：页面进入、导航、搜索、菜单开关、取消分支和控制台检查。
2. 写入验证：在隔离数据集内执行新建、编辑、收藏、分类、删除、导入导出和同步。
3. 故障验证：模拟无效输入、取消、离线、超时、损坏文件和权限拒绝。
4. 回归验证：修复后复现原始失败步骤，再覆盖相邻页面和共享模块调用方。

## 六、缺陷闭环规则

### 6.1 分级

| 等级 | 定义 | 处理要求 |
|---|---|---|
| P0 | 无法启动、数据丢失、隐私或安全风险、核心页面不可用 | 立即阻断测试和发布，修复后全量回归 |
| P1 | 核心流程失败，如保存、导入导出、同步或关键按钮不可用 | 当前迭代修复，覆盖所属页面和数据链路回归 |
| P2 | 非核心功能异常、跨端不一致、可恢复交互问题 | 登记排期，发布前完成风险评估和定向复测 |
| P3 | 低频体验、文案或不阻碍操作的轻微问题 | 集中处理，避免阻塞 P0/P1 闭环 |

### 6.3 修复与回归流程

1. 先以独立数据和精确步骤稳定复现，排除自动化坐标、浏览器会话和环境问题。
2. 根据证据定位路由、状态同步、事件绑定、存储边界、容器桥接或资源路径等根因。
3. 仅修改根因所在模块；共享逻辑修改必须识别并验证所有端侧调用方。
4. 复测原始失败路径、取消和失败分支、快速重复操作，再回归关联页面。
5. 可稳定自动化的缺陷必须新增回归测试；无法自动化时记录原因与人工复测步骤。
