# 目标计划清单功能实施计划

> 文档创建日期：2026-08-21
> 基线：当前 `src/js/pc-app.js`、`src/js/mobile-app.js`、`src/js/sqlite-storage.js`
> 目标：在左侧导航新增「目标计划」入口，支持按工程项目管理父子任务清单，并提供图片悬浮预览
> 技术栈：原生 JS + Vite + Capacitor 8.x (SQLite) + Tauri (JSON 文件存储)

---

## 一、功能范围

1. **导航入口**：PC 左侧导航与移动端底部导航（或更多入口）新增「目标计划」。
2. **项目列表页**：按工程项目维度展示清单入口，显示任务进度与最近更新时间。
3. **项目详情页**：进入项目后展示该项目的父子任务清单。
4. **任务管理**：父任务可折叠/展开，子任务缩进；支持勾选完成、状态联动。
5. **图片预览**：每条任务右侧显示小图标，悬浮时浮窗预览，点击放大。
6. **数据存储**：移动端 SQLite 新增项目/任务/图片关联表；PC 端 JSON 文件同步扩展。

## 二、数据结构设计

### 2.1 SQLite 表结构（移动端）

在 `src/js/sqlite-storage.js` 的 `init()` 中新增以下表：

```sql
CREATE TABLE IF NOT EXISTS goal_projects (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    sort_order INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS goal_tasks (
    id TEXT PRIMARY KEY,
    project_id TEXT NOT NULL,
    parent_id TEXT DEFAULT '',
    title TEXT NOT NULL,
    completed INTEGER DEFAULT 0,
    sort_order INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (project_id) REFERENCES goal_projects(id) ON DELETE CASCADE,
    FOREIGN KEY (parent_id) REFERENCES goal_tasks(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS goal_task_images (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL,
    path TEXT DEFAULT '',
    name TEXT DEFAULT '',
    created_at TEXT NOT NULL,
    FOREIGN KEY (task_id) REFERENCES goal_tasks(id) ON DELETE CASCADE
);
```

### 2.2 JSON 文件结构（PC 端）

PC 端在 `python/main.py` 维护的数据目录中新增 `goals.json`：

```json
{
  "projects": [
    {
      "id": "project-uuid",
      "name": "XX 工程项目",
      "order": 0,
      "createdAt": "2026-08-21T00:00:00.000Z",
      "updatedAt": "2026-08-21T00:00:00.000Z",
      "tasks": [
        {
          "id": "task-uuid",
          "title": "父任务标题",
          "completed": false,
          "order": 0,
          "createdAt": "2026-08-21T00:00:00.000Z",
          "updatedAt": "2026-08-21T00:00:00.000Z",
          "children": [
            {
              "id": "subtask-uuid",
              "title": "子任务标题",
              "completed": false,
              "order": 0,
              "images": ["relative/path/to/image.png"]
            }
          ]
        }
      ]
    }
  ]
}
```

### 2.3 图片存储

- 图片文件存放在数据目录下的 `goal_images/<project_id>/` 子目录中。
- 数据库/JSON 中只保存相对路径，不存 base64。
- 导入图片时复制到目标目录，删除任务时同步清理未引用的图片文件。

- `POST /api/goals/images/upload`：上传任务图片，返回相对路径。

#### 核心函数

- `calcTaskTreeStats(tasks)`：计算任务总数、已完成数、完成百分比。
- `isParentChecked(children)`：所有子任务完成则父任务完成；部分完成则半选。
- `flattenTasks(tree)`：将树形结构扁平化为数组，便于渲染。
- `buildTaskTree(flat)`：将扁平任务按 `parent_id` 重建为树。

### PC 端样式总览

PC 端目标计划页面统一按 `docs/设计文档/新拟态按钮设计规范.md` 进行新拟态风格重构，样式集中在 `src/css/pc/08-goal-plan.css`：

## 十、风险提示

| 风险项 | 影响 | 应对措施 |
|---|---|---|
| 父子任务自关联删除 | 误删整棵任务树 | 删除父任务时级联删除子任务，但需二次确认 |
| 图片文件残留 | 占用磁盘空间 | 删除任务/项目时清理未引用图片 |
| 双端数据结构不一致 | PC/移动数据同步异常 | 统一 `storage` 接口返回结构，字段命名一致 |
| 移动端底部导航项过多 | 界面拥挤 | 优先将入口放入设置页，后续再决定是否加入底部导航 |
| 任务排序实现复杂 | 拖拽跨层级逻辑混乱 | 一期仅支持同级排序，跨层级二期处理 |
