# 第三方图片引擎分发说明

## 分发范围

图片处理通过独立进程调用官方未修改的 jpegoptim 1.5.6 Windows x64 与 Oxipng 10.2.1。
许可证、上游说明和可执行文件摘要在源码附件中提供；安装目录的 `third-party/image-engine-sources.zip` 同时附带该源码材料，GitHub Release 另提供可独立下载的同内容附件。

## JPEG 对应源码与构建

- jpegoptim 1.5.6：GPL-3.0-or-later；完整源码来自上游同版本发布资产，包含 CMake、configure、Makefile 和 `.github/workflows/compile.yml` 等构建入口。
- 上游 Windows 工作流使用 MSVC、CMake、NASM，运行 `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_NO_SUBFOLDERS=1`，再运行 `cmake --build build --config Release`。
- 同版本 `CMakeLists.txt` 默认静态构建 MozJPEG v4.1.1。附件同时提供该版本完整源码及其中的许可文件。离线重建时可将 CMake 的 MozJPEG 外部下载来源替换为已解压的本地源码目录，或先构建它，再指定 `LIBJPEG_INCLUDE_DIR` 与 `LIBJPEG_LIBRARY`。
- 本项目未修改上述引擎源码；未承诺不同编译器和环境产生逐字节相同的二进制。
- 上游来源：[jpegoptim v1.5.6](https://github.com/tjko/jpegoptim/tree/v1.5.6)、[MozJPEG v4.1.1](https://github.com/mozilla/mozjpeg/tree/v4.1.1)。归档 URL 与固定 SHA256 见 `scripts/prepare_release_sources.py` 和附件内 `sources.json`。

## PNG 许可

Oxipng 的 MIT 许可证随 Sidecar 及源码附件提供；来源与二进制摘要见附件中的 `oxipng/engine.json`。

## 发布维护

先运行 `prepare_image_engines.py`，再运行 `prepare_release_sources.py`；正式 PC 构建脚本已串联两步。引擎版本变化时必须重新核对其源码、依赖和许可证，不能只改二进制摘要。安装包与源码附件必须同版分发；不将单独附带 LICENSE 视为完整源码提供。
