> 本文档是 `prompt-image-tool`（提示词管家）的结构性代码 Wiki，面向需要快速理解、维护或扩展该项目的开发者。内容覆盖前端、后端、桌面壳、移动端、构建与发布链路。

## 1. 项目概述

`prompt-image-tool` 是一款面向 Stable Diffusion / 生图工作流的**本地提示词管理器**。核心能力包括：

- 提示词集合（Prompt Set）与多版本（Version）管理
- 图片附件关联、压缩、预览与下载
- 文件夹与标签分类
- JSON / ZIP 备份与恢复
- 局域网多设备同步
- PC 端（Tauri + Python）与 Android 端（Capacitor）双端交付

项目采用**原生 HTML/CSS/JS 前端**（无 React/Vue 主框架），通过构建脚本分别打包为 Tauri 桌面应用与 Capacitor Android 应用。

## 4. 核心架构

### 4.1 运行时分层

```
┌─────────────────────────────────────────────────────────────┐
│                     前端 (Vanilla JS)                        │
│  PC 页面 / 移动页面 / 共享工具 / 主题服务 / 路由 / 存储抽象    │
├─────────────────────────────────────────────────────────────┤
│                     存储抽象层 (storage.js)                  │
│    PC: ApiStorage  ────────▶  Python HTTP API (localhost)   │
│  移动: SqliteStorage ──────▶  Capacitor SQLite + Filesystem  │
├─────────────────────────────────────────────────────────────┤
│  Tauri (PC)              │  Capacitor (Android)              │
│  - 启动 Python 后端      │  - SQLite 插件                    │
│  - 窗口管理              │  - 相册保存插件                   │
├─────────────────────────────────────────────────────────────┤
│  Python 后端 (PC)        │  本地 SQLite (移动)               │
│  - JSON 文件存储         │  - 同等数据模型                   │
│  - 图片文件存储          │  - Base64 图片存储                │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 关键设计决策

- **单一代码库多端复用**：PC 与移动端共用同一套前端页面与组件，通过 `detectUI()` 与 `storage.js` 在运行时切换实现。
- **无状态后端**：Python 后端不维持内存状态，所有数据持久化到 JSON 文件与图片目录，便于调试与迁移。
- **存储抽象**：业务模块只依赖 `getStorage()`，不直接感知 PC/移动差异。
- **主题双维度**：`appearance`（浅色/深色/系统/定时）+ `workbenchTheme`（品牌色主题）。

### 5.2 存储抽象层

- **入口**：[src/js/storage.js](file:///g:/Unity/prompt-image-tool-main/src/js/storage.js)
- **PC 实现**：[src/js/api-storage.js](file:///g:/Unity/prompt-image-tool-main/src/js/api-storage.js)
- **移动实现**：[src/js/sqlite-storage.js](file:///g:/Unity/prompt-image-tool-main/src/js/sqlite-storage.js)

`storage.js` 对外暴露：

| 函数 | 说明 |
|------|------|
| `initStorage()` | 创建并初始化存储实例 |
| `getStorage()` | 返回当前存储实例，供业务模块使用 |
| `isCapacitor` | 是否运行在原生的 Capacitor 环境 |

`ApiStorage` 关键行为：

- 启动后轮询 `/api/health` 等待后端就绪；
- 统一封装 `api(method, path, body)` 处理 JSON 请求与错误；
- 图片 URL 直接指向 `/images/<filename>`。

`SqliteStorage` 关键行为：

- 通过 `@capacitor-community/sqlite` 打开 `prompt_manager` 数据库；
- 表结构：`folders`、`prompt_sets`、`versions`、`images`；
- 图片以 Base64 `data:` URL 形式保存在 `images` 表中。

### 5.3 路由系统

- **PC 路由**：[src/js/pc-router.js](file:///g:/Unity/prompt-image-tool-main/src/js/pc-router.js)
- **移动路由**：[src/js/mobile-router.js](file:///g:/Unity/prompt-image-tool-main/src/js/mobile-router.js)

两套路由器 API 几乎一致，均基于 `history.pushState`/`popstate`：

| 函数 | 说明 |
|------|------|
| `registerRoute(path, handler)` | 注册路由，`path` 支持 `:id` 参数 |
| `navigate(path, params)` | 压栈导航 |
| `replace(path, params)` | 替换当前路由 |
| `goBack()` | 返回上一路由 |
| `navigateToTab(path)` | 底部 Tab 切换，清空栈 |
| `initRouter()` | 从 `history.state` 恢复路由状态 |
| `getCurrentRoute()` | 获取当前路由 |

History 快照：每次导航生成 `{ view, path, params, stack }` 对象写入 `history.state`，刷新或后退时可恢复。

## 6. 后端服务详解

### 6.1 Python HTTP 服务架构

- **开发入口**：[python/main.py](file:///g:/Unity/prompt-image-tool-main/python/main.py)
- **独立包入口**：[build/app_main.py](file:///g:/Unity/prompt-image-tool-main/build/app_main.py)

后端基于 `http.server.HTTPServer` + `SimpleHTTPRequestHandler`，端口固定 `8888`。核心类：

- `AppHandler(SimpleHTTPRequestHandler)`：所有 API 路由与静态文件服务；
- `ThreadingHTTPServer` 或其子类：多线程处理并发请求。

`AppHandler` 通过 `do_OPTIONS`、`do_GET`、`do_POST`、`do_DELETE` 分发请求。

### 6.2 数据目录与迁移

`get_data_dir()` 逻辑（`python/main.py`）：

1. 若环境变量 `PROMPT_IMAGE_TOOL_DATA_DIR` 存在，直接使用；
2. 否则使用用户数据根目录（Windows：`%APPDATA%\PromptImageManager`，其他：`~/.prompt-image-tool`）；
3. 创建 `data/images`、`data/backups`；
4. 调用 `migrate_legacy_data_if_needed()` 处理旧版数据迁移。

关键路径常量：

| 常量 | 路径 |
|------|------|
| `DATA_DIR` | `<data-root>/data` |
| `IMAGES_DIR` | `<data-root>/data/images` |
| `BACKUPS_DIR` | `<data-root>/data/backups` |
| `DATA_FILE` | `<data-root>/data/prompt_sets.json` |
| `FOLDERS_FILE` | `<data-root>/data/folders.json` |
| `SYNC_DEVICE_FILE` | `<data-root>/data/sync-device.json` |

同步端点：

| GET | `/api/sync/capabilities` | `handle_sync_capabilities()` | 本机能力 + IP |

安全：通过 `X-Sync-Token` Header 与 `secrets.compare_digest()` 做常量时间比对；配对码为 `sync_token` 后 6 位。

- [src-tauri/capabilities/default.json](file:///g:/Unity/prompt-image-tool-main/src-tauri/capabilities/default.json)：授予 `shell:allow-spawn`、`shell:allow-kill`。

### 7.2 启动逻辑

[src-tauri/src/lib.rs](file:///g:/Unity/prompt-image-tool-main/src-tauri/src/lib.rs) 的 `run()`：

1. 初始化 `tauri_plugin_shell`；
2. 非 Android 平台调用 `start_python_backend()`；
3. 查找 Python（`python`/`python3`/`python.exe` 或常见 Windows 路径）；
4. 从 Tauri 资源目录定位 `python/main.py`；
5. 以 `Command::spawn()` 启动 Python 子进程；
6. 主窗口加载前端 `index.html`。

[src-tauri/src/main.rs](file:///g:/Unity/prompt-image-tool-main/src-tauri/src/main.rs) 仅调用 `app_lib::run()`。
