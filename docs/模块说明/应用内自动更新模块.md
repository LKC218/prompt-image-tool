# 应用内自动更新模块

## 职责

PC 生产包（**Tauri + Sidecar**，见 [PC发包规范-Tauri主路径](../构建方案/PC发包规范-Tauri主路径.md)）通过应用内检查 GitHub Releases 的 `latest.json`，完成新版本发现、下载、SHA256 校验，并**拉起可见安装向导**（NSIS 交互安装）。安装过程对用户可见；安装完成后由向导完成页「立即启动」进入新版本。应用在向导拉起后退出以释放文件锁。

## 源码位置

| 文件 | 职责 |
| --- | --- |
| `python/auto_update.py` | 更新核心：拉元数据、比版本、异步下载 Job（进度/取消）、校验、**可见安装向导启动**（`CREATE_BREAKAWAY_FROM_JOB`，失败回退 `ShellExecuteW`） |
| `build/auto_update.py` | 生产侧同内容副本（随 `server.spec` Sidecar 打包） |
| `python/main.py` / `build/app_main.py` | HTTP 路由：`/api/update/check|download|progress|download/cancel|install` |
| `src/js/release/auto-updater.js` | 前端封装：检查 / 启动下载 / 轮询进度 / 取消 / 安装；更新会话互斥；确认框文案「暂不更新 / 下载安装」；请求经 `resolveApiBase()` 拼绝对地址（Tauri 壳下页面源与 Sidecar 不同源） |
| `src/js/release/update-progress-modal.js` | 更新进度弹窗：下载安装包 / 校验完整性 / **启动安装向导** 三阶段；installing/ready 不渲染操作钮 |
| `src/js/pc/pc-utils.js` | `showConfirmModal` 返回 Promise：确定 true，取消/Esc/遮罩/被覆盖 false |
| `src/js/pc/pc-app.js` | 侧栏常驻「检查更新」入口（更新记录旁） |
| `src/js/pc/pc-settings.js` | 设置页独立「软件更新」卡片 |
| `scripts/publish_release.ps1` | 发版时生成并上传 `latest.json` |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/update/check?localVersion=` | 比对远程 `latest.json` |
| POST | `/api/update/download` | `{url, sha256}` 启动后台下载，立即返回 `{jobId}` |
| GET | `/api/update/progress?jobId=` | 查询阶段与进度：`pending/downloading/verifying/ready/failed/cancelled` |
| POST | `/api/update/download/cancel` | `{jobId}` 请求取消，chunk 循环内生效并清理临时文件 |
| POST | `/api/update/install` | `{path, expectedVersion?}` **拉起可见安装向导**（无 `/S`、无 `/D=`、不预卸载）；随后退出当前应用 |

### 安装链路（Windows 生产包 / Tauri 主包）

1. `launch_installer_wizard(installer_path)` 校验安装包存在后 `Popen([setup])`。
2. 进程标志：`CREATE_BREAKAWAY_FROM_JOB | CREATE_NEW_PROCESS_GROUP`，保证主程序退出（Job 关闭 / `taskkill /T`）后安装向导仍存活并显示窗口。
3. **不**传 NSIS `/S`、**不**传 `/D=`、**不**应用内静默卸载：目录与流程由用户在向导中确认；覆盖安装与清进程交给 NSIS hook。
4. Popen 失败时回退 `ShellExecuteW`（`open`）；仍失败则接口报错，应用不退出。
5. 成功响应 `{success, mode: "wizard", installerPid, installerPath, launchMode}` 后：前端 `closeShellAfterInstall` 关闭 Tauri 主窗；后端约 0.3s `os._exit` 兜底。
6. 向导完成页勾选「立即启动」拉起新版本（非静默安装标准 MUI 行为）。
7. 诊断日志：`%TEMP%\prompt-image-update.log`。

> 历史方案（NSIS `/S` + PowerShell bootstrap 卸载→静默安装→强重启）已移除：静默链路在 Job/`taskkill /T` 下易出现「应用退出但未安装」。

## 发布元数据

发布验收应使用升级前的客户端读取固定 latest 地址，校验新版本发现、实际下载与 SHA256；冻结后端测试不代替安装向导、重启与用户资料保留验证。v2.5.32 沿用 v2.5.31 已支持的元数据字段和交互安装协议，无需旧客户端先更新检查逻辑。

`python/main.py` 的端口探测与 `LocalThreadingTCPServer` 在 Windows 使用独占绑定，不对已占用端口启用地址复用。可用端口仍从 8888 起顺序寻找，防止新旧服务同时占用同一端口。

`releases/latest.json` 由发布脚本生成，字段：`version` / `pub_date` / `notes` / `platform` / `url` / `sha256`。

托管地址：`https://github.com/LKC218/prompt-image-tool/releases/latest/download/latest.json`

## 维护说明

- 修改 `python/auto_update.py` 后必须同步 `build/auto_update.py`；修改 `python/main.py` 更新路由后同步 `build/app_main.py`。
- 发布后确认 Release 含 `latest.json`，且 `url` 指向本版本 Setup 包。
- 本地 `releases/` 维护：保留 `latest.json` + 当前最新 Setup 包即可。
- 启动检查失败静默；确认框「暂不更新」会跳过该远程版本（localStorage：`pc-update-skip-version`），手动检查会清除跳过。Esc / 点遮罩关闭等同取消。
- **Tauri 同源约束**：前端页面跑在 `tauri://` / `https://tauri.localhost`，Python Sidecar 在 `http://localhost:8888+`。所有 `/api/update/*` 必须经 `resolveApiBase()` 拼绝对地址。
- 同一时刻仅允许一个更新会话（确认→下载→安装）；并发进入直接返回 `busy`。
- 安装接口 **禁止** 再拼 `/S` 或 `/D=`；`expectedVersion` 仅签名兼容，不参与安装。
- 主 exe 候选（诊断用）：`生图提示词管理器.exe`（Tauri 主包）→ `PromptImageManager.exe`（应急 PyInstaller）→ `app.exe`。
- 入口：侧栏底栏横排（更新记录 / 检查更新 / 主题 / 设置）+ 设置页「软件更新」卡片。
- 确认更新后打开阶段式进度弹窗（下载安装包 / 校验完整性 / 启动安装向导）；下载中可取消，失败可重试。
- 网络加固：检查更新对每个候选 URL 最多重试 3 次；直连 GitHub 失败后回退 `ghproxy.net` / jsDelivr。安装包下载在 GitHub 直连失败时自动尝试 `ghproxy.net` 前缀镜像。
- **安装/卸载前清进程**：NSIS `NSIS_HOOK_PREINSTALL` / `NSIS_HOOK_PREUNINSTALL`（`src-tauri/nsis/installer-hooks.nsh`）结束主程序与 Sidecar；本模块不在应用内 `taskkill`。
- **退出回收**：Tauri `Exit` 对 Sidecar `kill+wait` + `taskkill /T`；安装向导已 `BREAKAWAY`，不受杀树影响。主窗由前端 `closeShellAfterInstall` 关闭。
