# 应用内自动更新模块

## 职责

PC 生产包（PyInstaller）通过应用内检查 GitHub Releases 的 `latest.json`，完成新版本发现、下载、SHA256 校验与 NSIS 静默安装。

## 源码位置

| 文件 | 职责 |
| --- | --- |
| `python/auto_update.py` | 更新核心：拉元数据、比版本、异步下载 Job（进度/取消）、校验、`/S` 安装 |
| `build/auto_update.py` | 生产侧同内容副本（PyInstaller 从 `build/` 打包） |
| `python/main.py` / `build/app_main.py` | HTTP 路由：`/api/update/check|download|progress|download/cancel|install` |
| `src/js/auto-updater.js` | 前端封装：检查 / 启动下载 / 轮询进度 / 取消 / 安装 |
| `src/js/update-progress-modal.js` | 阶段式更新进度弹窗（百分比、字节/速度、三阶段、取消/重试） |
| `src/js/pc-app.js` | 侧栏常驻「检查更新」入口（更新记录旁） |
| `src/js/pc-settings.js` | 设置页独立「软件更新」卡片 |
| `scripts/publish_release.ps1` | 发版时生成并上传 `latest.json` |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/update/check?localVersion=` | 比对远程 `latest.json` |
| POST | `/api/update/download` | `{url, sha256}` 启动后台下载，立即返回 `{jobId}` |
| GET | `/api/update/progress?jobId=` | 查询阶段与进度：`pending/downloading/verifying/ready/failed/cancelled` |
| POST | `/api/update/download/cancel` | `{jobId}` 请求取消，chunk 循环内生效并清理临时文件 |
| POST | `/api/update/install` | `{path}` 以 `/S` 启动安装器并退出应用 |

## 发布元数据

`releases/latest.json` 由发布脚本生成，字段：`version` / `pub_date` / `notes` / `platform` / `url` / `sha256`。

托管地址：`https://github.com/LKC218/prompt-image-tool/releases/latest/download/latest.json`

## 维护说明

- 修改 `python/auto_update.py` 后必须同步 `build/auto_update.py`；修改 `python/main.py` 更新路由后同步 `build/app_main.py`。
- 发布后确认 Release 含 `latest.json`，且 `url` 指向本版本 Setup 包。
- 启动检查失败静默；「暂不」会跳过该远程版本（localStorage：`pc-update-skip-version`）。
- 入口：侧栏底栏横排（更新记录 / 检查更新 / 主题 / 设置）+ 设置页「软件更新」卡片。
- 确认更新后打开阶段式进度弹窗（下载/校验/启动安装）；下载中可取消，失败可重试。轮询间隔约 250ms。
- 网络加固：检查更新对每个候选 URL 最多重试 3 次；直连 GitHub 失败后回退 `ghproxy.net` / jsDelivr（`@main/releases/latest.json`）。安装包下载在 GitHub 直连失败时自动尝试 `ghproxy.net` 前缀镜像。SSL/EOF 中断会转成可读中文错误。
