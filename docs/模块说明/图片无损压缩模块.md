# 图片无损压缩模块

## 当前职责

本文件描述 PNG 专项算法与兼容接口。PC 页面已扩展为「图片处理」，支持 PNG／JPEG／WebP；当前交互、缓存、限制与多格式 API 以 [图片处理模块](图片处理模块.md) 为准。

## PNG 保真契约

- `python/png_compress.py` 使用固定 Oxipng 10.2.1；等级 0–6、线程 1–4、优化预算 15／30／60 秒。默认 2／2／60，全部无损，不是质量百分比；等级高不保证文件更小。
- `--nx --interlace keep` 禁止颜色类型、位深和交错变换，不启用 `--alpha`、`--strip` 或 Zopfli。
- 输入检查签名、块长度、CRC、解压量与完整解码；拒绝 APNG、尾随内容和损坏图片。
- 输出逐项比较 IHDR 与全部非 IDAT 块及其顺序，通过 PyPNG 独立解码比较样本哈希，保护透明像素、16 位样本、调色板与提示词。
- 元数据变化则返回原图（preserved），无收益返回原图（unchanged），像素不符拒绝候选；无损优先于体积。
- 专属任务目录由 `image_cache.py` 管理，finally 回收；原文件从不写入。多格式入口遇到 PNG 原格式优化时直接复用本模块，忽略有损质量参数。
- 单图 20 MiB、1600 万像素、最大 128 MiB 解压量。进程上限 90 秒，前端请求 120 秒。预算只限制后续优化尝试。
- 信号量与取消注册表同时由多格式入口复用，取消支持先于处理请求到达。
- `compress` 的内部可选 `deadline` 接收多格式入口的同一绝对截止时间，避免启用尺寸但无需缩放时，预检之后重新获得完整的 90 秒引擎时限；旧 HTTP 参数和独立调用默认值不变。

## 兼容接口

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| `GET /api/png-compress/status` | 本机来源 | ready、version、token |
| `POST /api/png-compress?job=<uuid>` | PNG 字节、application/octet-stream、X-Png-Token | PNG 及 X-Png-Status |
| `POST /api/png-compress/cancel?job=<uuid>` | X-Png-Token | cancelled，表示收到指令 |

参数 level、threads、budget 后端独立校验；旧 mode=standard/deep 仍兼容。来源与令牌限制不等于用户登录认证，不防御已控制本机的攻击者。

## 准备与验证

`scripts/prepare_png_engine.py` 校验固定 Windows x64 引擎归档摘要，准备引擎、清单和 LICENSE；运行时不联网。多格式统一准备入口为 `scripts/prepare_image_engines.py`。

`python/tests/test_png_compress.py` 覆盖保真与边界；`scripts/png_validation_fixtures.py` 生成样本并回读 ZIP；`scripts/verify-png-compression.mjs` 在当前多格式页面回归 PNG 工作流。完整命令见 [脚本说明](../../scripts/README.md)。

最初设计及验收保留为历史证据：[PNG 实施计划](../计划与规格/04-新功能实装与增强/图片无损压缩-实施计划-261007.md)、[PNG 验收记录](../质量与复盘/图片无损压缩-验收记录-261007.md)。不代表当前安装包已验收。
