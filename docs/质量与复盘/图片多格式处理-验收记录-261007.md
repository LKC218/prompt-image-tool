# 图片多格式处理-验收记录

## 本轮范围

PNG、JPEG、静态 WebP 混合批量优化与转换；保持原工作台布局、轻拟态与共享插画；专属缓存清理。未发布安装包，未修改图库与同步协议。准备固定 Oxipng 10.2.1、jpegoptim 1.5.6、Pillow 12.3.0，保留引擎许可与来源。

## 验收证据

- 前端 Vitest：48 个文件、413 项通过。
- Python 全量：142 项通过（隔离测试数据目录）；专项覆盖九种源／目标组合、三格式无损、透明 JPEG 填充、无损 WebP 像素、高位深与 CMYK 拦截、动画拦截、参数确认、EXIF／ICC 快照、取消与超时、活跃租约、遗留缓存及失败回收。
- `npm run build` 通过；`npm run verify:dist-assets` 通过。
- `verify-image-processing.mjs`：三张混合样本，原格式无损、转换 JPEG、转换 WebP、转换 PNG 共四批成功；质量与填充设置、确认门槛、重新处理、ZIP 导出、缓存按钮、四种宽度及浅深色通过，无脚本错误。产物 `output/image-validation/`。
- 三种转换 ZIP 经 Python 回读，均为实际目标格式与原尺寸；PNG 专项 ZIP 七张逐一比较像素与元数据全部一致。产物 `output/png-validation/`。
- `verify-png-compression.mjs` 在新 API 下回归：七张 PNG 批量、文件夹去重、单图与 ZIP、坏图导入拦截、拖放、选择、取消、卸载、键盘、六主题浅深色及主导航通过。坏 CRC 现在在导入阶段拒绝，不再进入处理阶段。
- 人工查看 JPEG 转换设置、800 宽度与深色截图：共享横幅、条件设置、局部滚动与底部操作正常，主页面无横向溢出。

## 服务与复现

本轮使用 `http://127.0.0.1:5174/?ui=pc`，后端 `127.0.0.1:8898`，数据隔离在 `output/png-validation/profile`。既有 8888 服务未操作。完整复现命令见 [脚本说明](../../scripts/README.md)。测试输出与缓存均为忽略产物，不提交用户图片。
